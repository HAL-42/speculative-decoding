投机采样

Speculative Decoding

让小模型先猜，让大模型后验。生成速度快 2～3 倍，输出分布与大模型完全相同。

上面一行是普通解码：大模型每做一次前向，只能吐出一个 token。下面一行是投机采样：小模型先飞快地猜出几个 token（蓝色斜体），大模型一次性检查所有猜测，留下猜对的（绿色），从第一个猜错的位置（红色）开始改写成自己的答案（黄色）。

这里有三个问题值得追问：为什么这样会更快？大模型「检查」难道不要时间吗？凭什么一点不损失质量？毕竟小模型的猜测经常是错的。到底能快多少？这篇文章会一个一个回答，最后你应该能自己从头推出整个算法。

第一章

慢的根源：大模型在「等」，不是在「算」

先回顾一下语言模型怎样生成文本。给定前缀 $x_{<t}$，模型输出下一个 token 的分布 $p(\cdot \mid x_{<t})$，我们从中采样 $x_t$，把它接到前缀后面，再预测下一个……

$$x_t \sim p(\cdot \mid x_1,\dots,x_{t-1}),\qquad t = 1, 2, \dots$$

第 $t$ 个 token 必须等第 $t-1$ 个 token 确定以后才能开始算，所以生成 $K$ 个 token 需要 $K$ 次串行的前向计算。这件事乍看理所当然，但要理解投机采样，得先问一个更细的问题：一次前向的时间到底花在哪里？

算一笔账

以一个 70B 参数、FP16 存储的模型跑在一张 H100 上为例（忽略 KV cache，只算个大概）：

  • 搬运：每生成一个 token，所有权重都要从显存（HBM）读进计算单元一遍。140 GB ÷ 3.35 TB/s ≈ 42 ms。
  • 计算：一个 token 的前向大约需要 $2 \times 70\text{B} = 140$ GFLOP。H100 的稠密 BF16 算力约 989 TFLOPS，算完只要 0.14 ms。

两者差了约 300 倍。也就是说，以 batch=1 解码时，计算单元 99% 以上的时间都在等数据。这种情形叫访存受限（memory-bound）：瓶颈是显存带宽，不是算力。

由此可以推出一个关键结论：权重既然已经搬进来了，顺便多算几个位置几乎不花额外时间。拖动下面的滑块，看看一次前向同时处理 $k$ 个 token 时，耗时如何变化。

真实系统还有 KV cache 读取、kernel 开销和多卡通信，具体数字会不同，但「batch=1 解码严重访存受限」这个结论很稳健。

在 $k$ 达到几百之前，曲线几乎是平的：处理 1 个 token 和处理 5 个 token，耗时都约等于读一遍权重的 42 ms。这正是 prefill（一次性处理整段 prompt）比逐个生成快得多的原因。

关键矛盾 硬件希望一次处理很多 token，自回归依赖却规定一次只能确定一个 token。打个比方：开一辆大卡车往工地运砖，往返时间是固定的，多装几块砖几乎不费事；麻烦在于下一块砖要什么形状，得等这一块砌好了才知道。投机采样要做的，就是在这对矛盾之间撬开一道缝。
第二章

关键的不对称：检查比生成便宜

我们没法并行地生成多个 token，但可以并行地检查多个 token。

假设手里已经有一段候选续写 $\tilde x_1, \dots, \tilde x_\gamma$（先别管它从哪来）。把它接在前缀后面送进大模型，做一次前向。因果注意力保证每个位置只能看到自己和之前的 token，所以这一次前向会同时给出 $\gamma+1$ 个条件分布：

$$p(\cdot \mid x_{<t}),\;\; p(\cdot \mid x_{<t}, \tilde x_1),\;\; p(\cdot \mid x_{<t}, \tilde x_{1:2}),\;\; \dots,\;\; p(\cdot \mid x_{<t}, \tilde x_{1:\gamma})$$

这和训练时的 teacher forcing 完全是一回事：一次前向就能拿到序列中每个位置的预测。区别只在于这里的「标准答案」是别人猜的。

「串行」模式下，每一步都要等上一步的结果，5 个位置需要 5 次前向。「并行」模式下，草稿已经给定，5 个位置的分布一次前向就全部算完。
根据第一章的结论，这两种模式下单次前向的耗时几乎一样。

下面的注意力掩码说明了「一次前向得到多个位置的分布」为什么成立：第 $i$ 行（查询）只能看到第 $\le i$ 列（键），所以「核心」这一行算出的分布只依赖「…的 核心」，和后面的草稿无关。

因果掩码：黄色格子表示「可以看见」。KV cache 中已经缓存的前缀对所有位置可见。

一个熟悉的类比

写作文很慢，因为要一个字一个字地想；批改作文快得多，老师一眼能扫过整行。而且批改天然是并行的，整行字同时摆在眼前。

计算机体系结构里早有类似的思想：CPU 的推测执行（speculative execution）。分支条件还没算出来，处理器就按预测的方向继续执行；猜对了白赚时间，猜错了就丢掉结果重来。投机采样（speculative decoding）的名字正是从这里来的。Leviathan 等人的贡献是把这个思想推广到随机的场合：要「猜」的不是一个确定值，而是从一个分布中抽出的样本。

至此我们知道 只要有一段便宜的候选续写，大模型就能用约一次前向的代价把它检查完。剩下两个问题：
① 候选从哪来？最简单的答案是用一个小模型来猜。
② 怎样「检查」才能保证最终输出和大模型自己生成的分布一模一样？这是全文的核心，第四章专门讲。
第三章

心智模型：起草 → 验证 → 纠正

先给两个角色起名字：

$M_q$，分布 $q$草稿模型（draft / approximation model）：小、快，不太准。比如和目标模型同系列的小参数版本。
$M_p$，分布 $p$目标模型（target model）：大、慢、准。我们真正想从它的分布中采样。
$\gamma$每轮起草的 token 数（草稿长度）。

投机采样的一轮由三步组成：

  1. 起草：$M_q$ 自回归地采样 $\gamma$ 个 token $\tilde x_1, \dots, \tilde x_\gamma$，同时记下每个 token 的草稿概率 $q_i(\tilde x_i)$。共 $\gamma$ 次小模型前向，很便宜。
  2. 验证：$M_p$ 对「前缀 + 全部草稿」做一次前向，得到 $\gamma+1$ 个位置的分布 $p_1, \dots, p_{\gamma+1}$。
  3. 纠正：从左到右逐个检验草稿。遇到第一个被拒绝的 token，就用一个修正分布重新采样这个位置，然后丢弃它之后的所有草稿。如果全部通过，再从 $p_{\gamma+1}$ 额外采样一个 token，这个 token 是白送的。

下面逐步走一遍本页开头那句话的生成过程（$\gamma=4$）。每点一次「下一步」，前进一个阶段。

① 起草② 并行验证③ 逐个检验④ 纠正 / 奖励 第 1 / 6 轮
大模型调用 0 次 · 小模型调用 0 次 · 已生成 0 个 token

q 是草稿模型给自己所猜 token 的概率，p 是目标模型给同一个 token 的概率。
白色竖线是随机数 u，绿色区域是接受概率 min(1, p/q)。u 落在绿色区域内就接受。

回顾这个例子，有几点值得留意：

  • 每轮至少产出 1 个 token。第 3 轮第一个草稿就被拒绝了，但大模型那次前向并没有白做，它仍然产出了一个纠正 token。所以最坏情况下，投机采样只比普通解码多花了起草的成本。
  • 每轮最多产出 $\gamma+1$ 个 token。第 2、4 轮全部草稿都被接受，外加 1 个奖励 token。
  • 拒绝之后必须丢弃后面的所有草稿。它们是在错误前缀上生成的，大模型为它们算的分布也基于错误前缀，所以全部作废。
  • 容易的 token（「采样」紧跟「投机」、句末的「。」）小模型基本都能猜对；难的、需要「思考」的 token（「快速」「并行」），由大模型亲自给出。
心智模型
  1. 大模型的时间是按「次」计费的，不是按 token 计费：一次前向处理 1 个 token 还是 5 个，价钱差不多。
  2. 投机采样把很多次计费合并成一次：便宜的模型提出假设，昂贵的模型一次性审阅，从第一个分歧处纠正。
  3. 文本中有大量「显而易见」的 token，小模型就能猜对；越是这样的文本，加速越明显。

还剩一个关键问题没有回答：检验规则到底是什么？如果是贪心解码（temperature = 0），规则很直观：草稿 token 等于大模型的 argmax 就接受。可我们通常要采样，这时大模型对同一个前缀也可能输出不同的 token，「猜对」该怎么定义？上面例子里的 $\min(1, p/q)$ 又是从哪来的？

第四章

核心：怎样做到一点不差？

先把问题从语言模型里抽象出来。只看一个位置：

问题 手里有一个样本 $\tilde x \sim q$，还知道两个分布 $p$、$q$ 的完整概率表（大模型那一次前向把 $p$ 算出来了）。我们想输出一个 $X$，满足：
① $X$ 严格服从 $p$；
② 尽可能经常直接用 $\tilde x$，即让 $P(X = \tilde x)$ 尽量大。

先看两种朴素的做法：

  • 总是接受 $\tilde x$。输出服从 $q$，质量退化成小模型的水平，不满足 ①。
  • 大模型自己再独立采样一次，两者恰好相同才接受。这满足 ①，但非常浪费。设想 $p$ 和 $q$ 完全一样，都是 100 个 token 上的均匀分布：草稿明明完美，却只有 1% 的概率被接受。（这个例子来自 Google Research 的回顾博客。）

第二种做法的问题在于它只用了「样本」，没有用「概率」。既然 $p$、$q$ 的概率表都在手上，就能做得聪明得多。

修正拒绝采样（modified rejection sampling）

规则只有两条：

  1. 以概率 $\displaystyle \min\!\Big(1,\ \frac{p(\tilde x)}{q(\tilde x)}\Big)$ 接受 $\tilde x$。也就是说，若 $q(\tilde x) \le p(\tilde x)$（草稿低估了这个 token）就直接接受；若 $q(\tilde x) > p(\tilde x)$（草稿高估了它）就只以 $p/q$ 的概率接受。
  2. 若拒绝，从残差分布中重新采样： $$p'(x) = \frac{\max\big(0,\; p(x) - q(x)\big)}{\sum_{x'} \max\big(0,\; p(x') - q(x')\big)}$$

第一条容易理解：草稿高估了的 token，接受时就打个折。第二条比较神秘：为什么偏偏是 $\max(0, p-q)$？下面的图会让它变得显然。

一幅图看懂

把 $q$ 画成一排柱子。「从 $q$ 中抽样 $\tilde x$，再抽 $u \sim U(0,1)$」等价于在蓝色柱子覆盖的区域里均匀撒一个点：点的横坐标是 $\tilde x$，纵坐标是 $u \cdot q(\tilde x)$。接受条件 $u < p/q$ 等价于 $u \cdot q < p$，即这个点落在 $p$ 的高度以下。

按 ①②③ 的顺序点一遍。你可以在图上拖动修改柱子的高度（先选择改 q 还是 p），或者把鼠标悬停在某一列上查看具体数字。

接受：min(p,q) 拒绝：(q−p)₊ 缺口：(p−q)₊

例子：前缀「今天天气很」之后，草稿模型和目标模型对下一个词的分布。

图上的三步依次说明了：

  • 绿色（接受的部分）：在每一列上恰好是 $\min(p(x), q(x))$。草稿高估的列，绿色被截在 $p$ 的高度；草稿低估的列，绿色就是整根蓝柱。
  • 红色（被拒绝的部分）：是 $q$ 超出 $p$ 的那一截，$\max(0, q - p)$。它的总面积就是拒绝概率 $1-\beta$，其中 $\beta = \sum_x \min(p, q)$。
  • 缺口：要得到 $p$，绿色还差 $p$ 超出 $q$ 的那一截，$\max(0, p - q)$。

关键在于：红色的总量恰好等于缺口的总量。因为两者都等于 $1 - \sum_x \min(p, q)$：

$$\sum_x \max(0, q-p) = \sum_x \big(q - \min(p,q)\big) = 1-\beta = \sum_x \big(p - \min(p,q)\big) = \sum_x \max(0, p-q)$$

所以被拒绝时，只需把这份「多出来的」概率按缺口的形状重新分配，就能把绿色补成完整的 $p$。「按缺口形状分配」写成公式，就是残差分布 $p' \propto \max(0, p-q)$。神秘的第二条规则其实是在填坑。

严格证明

输出 $X = x$ 只有两种途径：草稿恰好是 $x$ 并被接受；或者草稿（不论是什么）被拒绝，再从 $p'$ 中重新抽到 $x$。

$$P(X=x) = \underbrace{q(x)\cdot\min\!\Big(1,\frac{p(x)}{q(x)}\Big)}_{\text{抽到 } x \text{ 且被接受}} \;+\; \underbrace{(1-\beta)\cdot p'(x)}_{\text{被拒绝后重抽到 } x}$$

第一项化简为 $\min(p(x), q(x))$。第二项中，$p'$ 的归一化常数正是 $\sum_{x'} \max(0, p-q) = 1-\beta$，与拒绝概率相互抵消：

$$(1-\beta)\cdot \frac{\max(0, p(x)-q(x))}{1-\beta} = p(x) - \min(p(x), q(x))$$

两项相加：

$$P(X = x) = \min(p(x),q(x)) + p(x) - \min(p(x),q(x)) = p(x) \qquad \blacksquare$$

证明对任意的 $q$ 都成立。草稿模型再差，也只会降低速度，不会降低质量。

接受率的含义

接受概率 $\beta$ 有一个漂亮的解释：

$$\beta = \sum_x \min(p(x), q(x)) = 1 - \tfrac{1}{2}\sum_x |p(x) - q(x)| = 1 - D_{\mathrm{TV}}(p, q)$$

它等于 1 减去两个分布的总变差距离，也就是两条分布曲线重叠部分的面积。草稿与目标越像，接受率越高。在上面的图里点「完全相同」，$\beta$ 变成 1；点「差异很大」，$\beta$ 明显下降。

它还是最优的：对于任何满足 $X \sim p$、$\tilde x \sim q$ 的联合分布（耦合），都有 $P(X = \tilde x) \le \sum_x \min(p, q)$，因为 $P(X = \tilde x = x)$ 不可能超过 $p(x)$，也不可能超过 $q(x)$。修正拒绝采样恰好取到这个上界（它是一种最大耦合，maximal coupling）。在只有一个草稿样本的前提下，不可能有更高的接受率。

与经典拒绝采样的区别：经典拒绝采样需要一个上界 $M \ge \max_x p(x)/q(x)$，以 $p/(Mq)$ 的概率接受，否则反复重试。它的单次接受率 $1/M$ 往往远低于 $\beta$，而且重试次数没有上界。修正版本把「重试」换成了「从残差中精确补齐」，一次就保证结束。
阅读论文时注意符号：Leviathan 等人（2022）用 $p$ 表示目标、$q$ 表示草稿，本文与之一致；DeepMind 的 Chen 等人（2023）恰好反过来，用 $q$ 表示目标、$p$ 表示草稿。
第五章

亲手验证：蒙特卡洛实验

证明说服的是头脑，实验说服的是直觉。下面真的按规则一个一个地采样：先在蓝色柱子里撒点（相当于从 $q$ 中抽取草稿），落在 $p$ 以下变绿（接受），否则变红（拒绝），再按某种方式重新采样一个金色点。右边统计最终输出的频率，并与 $p$ 比较。

可以切换到两种「错误」的纠正方式，看看会发生什么。分布与上一章的图共享，在上一章里修改了分布，这里会同步更新。

右图：灰色柱是实验频率，黄色框是目标分布 p，白色虚线框是当前方式的理论分布。
TV 是实验分布与 p 的总变差距离，越接近 0 越好。

选「拒绝后直接从 $p$ 采样」时，结果会系统性地偏向草稿高估的 token（比如「好」）。原因是接受环节已经从这些 token 上拿到了 $\min(p, q)$ 的概率，即已经用掉了一部分「配额」；拒绝后再从完整的 $p$ 里抽，又给了它们一份，等于重复计算。这种方式的输出分布是

$$\min(p, q) + (1-\beta)\,p \;\neq\; p$$

残差分布 $\max(0, p - q)$ 的含义正是「$p$ 中还没有被满足的那部分」，只往缺口里补，才能分毫不差。

第六章

完整算法与它的正确性

把单步的修正拒绝采样沿着草稿序列一个接一个地用下去，就得到完整算法（Leviathan et al. 2022, Algorithm 1）：

输入：已确定的前缀 prefix，草稿模型 M_q，目标模型 M_p，草稿长度 γ

// ① 起草：草稿模型串行地猜 γ 个 token（便宜）
for i = 1 … γ:
    q_i ← M_q(prefix + x̃₁ … x̃_{i−1})
    x̃_i ~ q_i

// ② 验证：目标模型一次前向，并行得到 γ+1 个分布
p_1, …, p_{γ+1} ← M_p(prefix + x̃₁ … x̃_γ)

// ③ 从左到右检验
for i = 1 … γ:
    r ~ U(0, 1)
    if r < min(1, p_i(x̃_i) / q_i(x̃_i)):
        接受 x̃_i
    else:
        y ~ norm( max(0, p_i − q_i) )          // 从残差中纠正
        return prefix + x̃₁ … x̃_{i−1} + y       // 丢弃 x̃_i 之后的所有草稿

// ④ 全部接受：从最后一个分布中免费多采一个
y ~ p_{γ+1}
return prefix + x̃₁ … x̃_γ + y

为什么多个 token 也是精确的？

用归纳法。设已经确定的前缀是 $x_{<t}$：

  • 第一个草稿 $\tilde x_1$ 是在真实前缀 $x_{<t}$ 下从 $q(\cdot\mid x_{<t})$ 抽取的，$p_1$ 也是在同一前缀下算的。由单步引理，这个位置的输出 $x_t \sim p(\cdot\mid x_{<t})$。
  • 若 $\tilde x_1$ 被接受，则 $x_t = \tilde x_1$，于是 $\tilde x_2$ 恰好是在真实前缀 $x_{\le t}$ 下抽取的，$p_2$ 也恰好以 $x_{\le t}$ 为条件。再用一次引理，得 $x_{t+1} \sim p(\cdot \mid x_{\le t})$。依此类推。
  • 若某个位置被拒绝，这个位置由残差纠正（仍服从 $p$），后面的草稿全部作废，下一轮从新的真实前缀重新开始。
  • 若全部接受，$p_{\gamma+1}$ 是以完整的真实前缀为条件算出来的，直接从中采样一个奖励 token 完全合法。

每个位置的条件分布都是 $p$，由链式法则，整个序列服从 $\prod_t p(x_t \mid x_{<t})$，和只用大模型逐个生成完全相同。

贪心解码：一个退化特例

temperature = 0 时，$p$ 和 $q$ 都退化成 one-hot 分布。接受概率 $\min(1, p/q)$ 只可能是 1（草稿等于大模型的 argmax）或 0；残差分布就是大模型 argmax 处的 one-hot。整个算法退化为「猜对就收下，猜错就换成大模型的答案」。这时的输出与普通贪心解码逐字相同（不计浮点误差）。

temperature、top-k、top-p 怎么办？

先对两个模型的 logits 做同样的变换（缩放温度、截断 top-k/top-p、重新归一化），得到它们实际用于采样的分布，把这两个分布当作 $p$、$q$ 代入检验即可。这样保证的是「和你原本的采样配置下，大模型的输出分布一样」。Chen 等人报告，接受率对这些参数的具体取值并不敏感。

「无损」的准确含义：保证的是分布相同，而不是「同一个随机种子生成同一句话」。另外，批量验证与逐个解码在浮点运算的累加顺序上可能不同，所以严格来说是「在硬件数值精度内」无损（Chen 等人的原话是 within hardware numerics）。
有损变体：有些方法会故意放宽检验来换取更高的接受率，比如 Medusa 的 typical acceptance，或者 Leviathan 论文附录里的 lenience 参数。它们更快，但不再保证分布完全一致，使用时要心里有数。
第七章

能快多少？

引入两个量：

  • 平均接受率 $\alpha = \mathbb{E}[\beta]$：一个草稿 token 被接受的平均概率，由模型和任务决定。
  • 成本系数 $c$ = 草稿模型一次前向的耗时 ÷ 目标模型一次前向的耗时，由硬件和实现决定。

Leviathan 等人做了一个简化假设：各位置是否被接受相互独立，且接受概率都是 $\alpha$。记每轮产出的 token 数为 $N$。$N \ge n$ 当且仅当前 $n-1$ 个草稿全部被接受，所以 $P(N \ge n) = \alpha^{n-1}$，$n = 1, \dots, \gamma+1$。用「尾概率求和」公式：

$$\mathbb{E}[N] = \sum_{n=1}^{\gamma+1} P(N \ge n) = \sum_{n=1}^{\gamma+1}\alpha^{n-1} = \frac{1-\alpha^{\gamma+1}}{1-\alpha}$$

这是一个被截断在 $\gamma+1$ 处的几何分布。每轮的耗时是 $\gamma$ 次草稿前向加 1 次目标前向，即 $\gamma c + 1$（以目标模型一次前向为单位；这里用到了第一章的结论：验证 $\gamma+1$ 个 token 与生成 1 个 token 耗时相当）。于是墙钟时间的加速比为：

$$\text{加速比} = \frac{1-\alpha^{\gamma+1}}{(1-\alpha)(\gamma c+1)}$$

前两个预设的 α 取自 Leviathan 等人论文的表 2，c≈0.015 取自其正文；论文实测加速分别为 3.4× 和 2.6×，略高于这里的理论估算。

几点观察

  1. $\alpha$ 是收益的主要来源。$\gamma=4$ 时，$\alpha$ 从 0.6 提高到 0.8，$\mathbb{E}[N]$ 就从 2.31 增加到 3.36。这也是后来大量工作致力于「让草稿更像目标」的原因。
  2. $\gamma$ 不是越大越好。$\mathbb{E}[N]$ 有上限 $1/(1-\alpha)$，成本 $\gamma c + 1$ 却线性增长，所以存在一个最优的 $\gamma^*$，可以简单地数值求出。Chen 等人的实验也观察到：$K$ 增大后加速比先进入平台期，再开始回落，同时延迟的方差越来越大。
  3. 只要 $\alpha > c$ 就一定有收益。取 $\gamma=1$ 时加速比为 $(1+\alpha)/(1+c)$，只要 $\alpha > c$ 就大于 1（论文推论 3.9）。
  4. 最坏情况有保底。每轮至少产出 1 个 token，所以最坏也只慢 $(\gamma c + 1)$ 倍，草稿越便宜损失越小。
  5. 独立同分布只是近似。实际中接受率随上下文剧烈波动：代码里的重复结构、固定格式、复述 prompt 原文，接受率极高；开放式创作、高温采样，接受率较低。这启发了动态调整草稿长度和草稿树形状的方法（如 EAGLE-2）。

真实的数字

  • Leviathan et al. (2022)：T5-XXL（11B）作目标，T5-small（77M）作草稿，英德翻译任务提速 2.6×（采样）～3.4×（贪心），输出完全一致。
  • Chen et al. (2023, DeepMind)：Chinchilla 70B，分布式部署下提速 2～2.5×。他们注意到，用了投机采样后的平均吞吐常常超过由显存带宽决定的自回归理论上限。
  • EAGLE-3 (2025)：在对话和推理模型上提速最高 6.5×。
第八章

家族谱系：草稿从哪里来？

「起草 → 并行验证」这个框架对草稿的来源没有任何要求。草稿越准（$\alpha$ 大）、越便宜（$c$ 小）就越好。围绕这两个目标，几年间出现了大量变体：

独立草稿模型

经典投机采样

用同系列的小模型当草稿（Leviathan 2022；Chen 2023）。即插即用，无需训练。

要求：词表与分词器必须一致。缺点：要额外部署一个模型，分布对齐不够好时 α 偏低。DistillSpec 用知识蒸馏让草稿模型更贴近目标模型。

多头预测

Medusa

在大模型最后一层的隐藏状态上加 K 个额外的解码头，第 k 个头直接预测往后第 k+1 个 token，再用树形注意力一次验证多种组合。

Medusa-1（冻结主干）提速约 2.2×；Medusa-2（联合微调）提速 2.3～2.8×。

特征层自回归

EAGLE 系列

EAGLE 用一个单层 decoder 在大模型倒数第二层的特征上自回归，并输入「提前一步的 token」来消除采样带来的不确定性；EAGLE-2 利用草稿置信度近似接受率，动态构造草稿树；EAGLE-3 改为直接预测 token，并融合低、中、高层特征，配合 training-time test 训练。

EAGLE：LLaMA2-Chat 70B 上提速 2.7～3.5×。EAGLE-3：最高 6.5×。

多 token 预测

MTP 模块

DeepSeek-V3 在训练时加入了 MTP（multi-token prediction）模块，推理时可以直接拿来当草稿。

报告中第二个 token 的接受率为 85%～90%，生成速度（TPS）约为原来的 1.8 倍。

自投机

跳层 / 早退

用大模型自己的一部分层做草稿，比如跳过若干中间层（Draft & Verify）或者在浅层提前退出（LayerSkip）。不需要额外参数，也不需要第二个模型。

无需模型

Prompt Lookup / Lookahead

Prompt Lookup Decoding：在 prompt 中做 n-gram 字符串匹配，把匹配位置之后的 token 复制过来当草稿，适合摘要、文档问答、代码修改等「抄原文」的任务（约 2～4×）。Lookahead Decoding：用 Jacobi 迭代并行生成 n-gram 池，同样不需要草稿模型。

树形验证：一次检查多种猜测

单条草稿链有个弱点：第一个 token 一旦猜错，后面全部浪费。既然一次前向还有大量空闲算力，不妨同时提出多条候选。把它们合并成一棵前缀树，展平成一个序列送进大模型，再把注意力掩码改成「每个节点只能看见自己的祖先」，位置编码按节点在树中的深度设置。这样一次前向就能验证整棵树（SpecInfer、Medusa、EAGLE 都这样做）。

把鼠标悬停在树的节点或掩码的某一行上：该节点能「看见」的正是它到根的路径。
6 个候选 token 只占一次前向，却包含了 4 条不同的续写路径。

验证时沿着树往下走，在每个节点决定接受哪个子节点。在采样（非贪心）设置下，要保持分布不变，需要把单草稿的修正拒绝采样推广到多个候选的情形（SpecInfer 给出了这样的多候选投机采样方法）。代价是每次前向处理的 token 变多，越接近计算受限，收益越递减。Medusa 的实验中，精心设计的 64 节点稀疏树，每步的加速率反而高于 256 节点的稠密树；而树太大时，实际速度会因为计算受限而下降。

第九章

工程实践中的要点

  • KV cache 回滚。被拒绝位置及其后面的 KV 必须丢弃（通常只需截断长度指针，在 PagedAttention 中就是截断或释放对应的 block）。草稿模型的 KV cache 也要同步回滚。
  • Batch size 是最大的变量。投机采样本质上是用空闲算力换延迟。batch 很大时，单次前向本来就接近计算受限，额外的 $\gamma$ 个位置不再免费，收益缩小，甚至可能拖慢吞吐。不过在长上下文场景下，读取 KV cache 会让解码重新变回访存受限，这时投机采样在大 batch 下也有收益（MagicDec）。EAGLE-3 在 SGLang 中 batch=64 时仍有约 1.38× 的吞吐提升。
  • 词表必须一致。否则 $p$ 和 $q$ 不在同一个空间里，无法逐 token 比较。
  • 采样参数要一致。$p$ 和 $q$ 都要使用经过同样 temperature/top-p 变换之后的分布。
  • 选好 γ。根据实测的 $\alpha$ 和 $c$ 选取，或者采用动态策略（按草稿置信度提前停止、动态树）。
  • 看对指标。「平均接受长度」（每轮产出的 token 数）高，不等于墙钟时间快，因为树越大，单次前向越慢。最终要看端到端的延迟和吞吐。
  • 框架支持。vLLM、SGLang、TensorRT-LLM、llama.cpp 都内置了投机解码；Hugging Face transformers 中可以用 assistant_model（草稿模型）或 prompt_lookup_num_tokens（Prompt Lookup）参数开启。
什么时候收益最大 低 batch、对延迟敏感（交互式对话、代码补全）；输出可预测性高（代码、结构化输出、摘要、改写）；草稿与目标对齐得好（同源模型、蒸馏、EAGLE 类草稿头）。
反过来，大 batch 的离线吞吐任务、草稿与目标差异很大、或者草稿不够便宜时，就要实测再决定。

总结

一页纸总结

把整件事串起来
  1. 动机：小 batch 解码是访存受限的。一次前向处理 1 个 token 和处理几个 token 耗时几乎一样，大模型的时间按「次」计费。
  2. 机会：生成必须串行，检查却可以并行。一次前向就能得到所有草稿位置上的分布。
  3. 流程：小模型起草 γ 个 → 大模型一次前向验证 → 从左到右接受，在第一个拒绝处用残差纠正，全部通过则额外奖励 1 个。每轮产出 1 到 γ+1 个 token。
  4. 正确性：以 $\min(1,p/q)$ 接受，被接受的概率质量恰好是 $\min(p,q)$；拒绝时从 $\max(0,p-q)$ 中重抽，恰好补满缺口，合起来正好是 $p$。接受率 $\beta = 1 - D_{\mathrm{TV}}(p,q)$，并且是最优的。
  5. 收益：$\dfrac{1-\alpha^{\gamma+1}}{(1-\alpha)(\gamma c+1)}$。$\alpha$ 越大越好，$c$ 越小越好，$\gamma$ 有最优值。
