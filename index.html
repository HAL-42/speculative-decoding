01 / THE BOTTLENECK

GPU 很忙，
但你仍在等下一个词。

要生成第 100 个 token，通常得先知道前 99 个。
这条依赖链，把一次回答串成了许多次等待。

自回归语言模型定义的是下一个 token 的条件分布。拿到这个分布、抽出一个 token、把它接到前缀，再算下一个。即使每步都很快，串行重复几百次也会累积出明显延迟。

p(x₁, …, xₙ | h) = ∏t = 1 … n p(xₜ | h, x₁, …, xₜ₋₁)h 是已经确认的上下文；每一步都依赖前面的实际输出。

在小 batch、访存受限的解码中，模型每一步都要读取大量权重和 KV cache，运算单元却未必满负荷。额外算几个位置的成本，可能远小于重新启动几次大模型前向。这给“花更多计算，减少串行等待”留下了空间。[3]

现在加入一个便宜的助手：它用很短的时间猜出接下来几个 token。如果大模型可以一次检查整段草稿，就有机会把几次昂贵等待合并成一次。

02 / THE ASYMMETRY

写出未知的未来很难，
检查给定的未来可以并行。

草稿的价值，是把“还不知道的输入”变成“已经给定的输入”。

生成时，第二个位置需要先抽出第一个 token。验证时，草稿 x₁, x₂, x₃, x₄ 已经摆在桌面上：大模型可以在一次带因果掩码（causal mask）的前向里，同时计算各位置的条件分布。[4]

这和训练时已知整段文本、同时预测各位置下一个 token 的计算方式相似。并行的是同一层内的多个位置，网络的层与层之间仍然顺序计算。

例如 p₃ 只依赖 h, x₁, x₂。因此，只要前两个草稿被接受，它就是第三个位置所需的正确分布。如果第二个被拒绝，第三个位置已算出的分布虽然数值有效，条件上下文却不再是我们实际采用的上下文，必须丢弃。

①

起草

便宜的小模型向前走几步，提出一条候选路径。

②

验证

大模型一次算出路径上所有条件分布，再从左向右判定。

③

接回真实路径

保留接受的前缀，纠正首个拒绝处，从新前缀继续。

THE MENTAL MODEL

把草稿想成一条暂时搭好的桥。只保留从起点连续验收通过的部分；第一处断掉后，桥后面的路也不能继续用。

候选 token 还不是最终输出。只有接受的连续前缀和新抽出的纠正 / 额外 token 才会提交。

接受并不要求草稿是大模型的最高概率 token。比如草稿给 A 的概率是 0.4，而目标只有 0.1，我们就只保留四分之一的 A 提案。这样，A 通过草稿进入最终输出的概率恰好是 0.4 × ¼ = 0.1。

若 4 个草稿全部接受，最后一个草稿位置已经给出了下一 token 的目标分布，直接再抽一个就能前进 5 个 token。这就是经常出现的 γ + 1，其中 γ 是草稿长度。[1]

04 / CONSERVATION OF PROBABILITY

把多的削掉，
把少的补回来。

投机采样的数学核心，可以看成一次概率面积的重新分配。

暂时忘记整段文本，只看同一个已确认前缀下的下一 token。记目标分布为 p，草稿的实际采样分布为 q；两者都归一化为 1。我们的目标是：从 q 出发，最后仍得到服从 p 的样本。

先看两幅分布的重叠。对任意 token，草稿提供得太多，就随机删去多余部分；草稿提供得不足，就全部接收。保留下来的质量正好是 min(p, q)。剩下的缺口 (p − q)₊，留给拒绝之后的补偿采样。

绿色是两者重叠的概率质量；金色轮廓是目标 p，蓝色虚线轮廓是草稿 q。把绿色保留，把金色的缺口补齐。

规则从哪里来？

草稿抽到 x 的概率是 q(x)。要让它最终保留下来的质量等于 min(p(x), q(x))，接受概率就必须是：

a(x) = min(1, p(x)q(x))先抽 x ∼ q，再抽 u ∼ Uniform[0, 1)；若 u < a(x) 则接受。

被拒绝时，我们已经知道这次落进了“草稿多给的区域”。要把总分布修正回来，应把这次机会分配给目标还缺的区域，并将这些缺口归一化：

r(x) = [p(x) − q(x)]₊∑v [p(v) − q(v)]₊[z]₊ = max(z, 0)。r 是“已发生拒绝”这一条件下的重采样分布。

整体的“起草—验证”流程称为投机解码（Speculative Decoding），其中保持分布的采样规则称为投机采样（Speculative Sampling）。本页统一采用 p = 目标、q = 草稿。Chen 等人的论文使用相反的字母约定；阅读时请对应角色。[2]

把图变成一个短证明

从接受通道到达 x

提议 x，再接受它。两件事的联合概率是：

P(Y = x, 接受) = q(x) a(x) = min(p(x), q(x))

拒绝的总质量，恰好等于缺口总质量

p 和 q 的总面积都是 1，多出来和少掉的面积必然相等。令 Z 表示拒绝概率：

Z = 1 − ∑x min(p(x), q(x)) = ∑x [p(x) − q(x)]₊

从补偿通道到达 x，再把两条通道相加

拒绝发生的概率 Z，乘上补偿分布 r(x)，刚好填上该 token 缺失的质量：

P(Y = x, 拒绝) = Z · r(x) = [p(x) − q(x)]₊
min(p(x), q(x)) + [p(x) − q(x)]₊ = p(x)

无论 q 多么不准确，最终输出 Y 都服从目标分布 p。

先点“+ 10,000 次”。TV 是频率与 p 的总变差距离；有限样本会有波动，实验验证直觉，严格结论来自上面的证明。

为什么拒绝后不能直接从 p 重抽？ 因为接受通道已经贡献了一部分概率。再按完整的 p 分配拒绝机会，会得到 min(p, q) + Zp，通常不等于 p。在初始例子中，错误方法的极限分布为 [0.14, 0.28, 0.32, 0.26]。

接受率也有了几何意义：

α = ∑x min(p(x), q(x)) = 1 − 12∑x |p(x) − q(x)|α = 1 − TV(p, q)。分布越重叠，草稿越容易被接受。
边界情况：q(x) = 0 或 p = q 怎么处理？

若 q(x) = 0，草稿根本不会提议 x，因此无需计算该处的 p(x)/q(x)。如果 p(x) > 0，x 仍可以通过补偿分布出现。若 p = q，所有提议都接受，Z = 0，补偿分布无需构造。数值实现应只在真正发生拒绝时归一化残差。

05 / FROM ONE TOKEN TO A SEQUENCE

局部概率守恒，
为什么能保护整段文本？

因为每次继续之前，我们都站在一个已经确认的前缀上。

把单步规则放回自回归链。第 i 个位置使用 qᵢ(· | h, x<ᵢ) 与 pᵢ(· | h, x<ᵢ)。在它之前的草稿全部接受时，候选前缀就是最终前缀，因此单步证明仍然适用。

一旦拒绝，立即丢弃后面的候选与相应验证结果；从当前正确前缀的残差分布补一个 token。这样逐步应用条件概率的链式法则，得到的整个序列分布与目标自回归采样一致。

一轮投机采样 · 语言无关伪代码p: target / q: draft
# h: 已确认前缀；γ: 本轮草稿长度
for i = 1 ... γ:
    q[i] = draft_distribution(h + x[1:i-1])
    x[i] ~ q[i]

# 同一次因果前向，得到 γ + 1 个位置的分布
p[1:γ+1] = target_verify(h, x[1:γ])

for i = 1 ... γ:
    u ~ Uniform[0, 1)
    if u < min(1, p[i][x[i]] / q[i][x[i]]):
        accept x[i]
    else:
        r = normalize(max(p[i] - q[i], 0))
        z ~ r
        return h + x[1:i-1] + [z]

# 全部通过，使用已经算出的下一个分布
z ~ p[γ+1]
return h + x[1:γ] + [z]

数组采用从 1 开始的闭区间。伪代码省略缓存实现；实际生成一旦提交 EOS 或达到长度限制就停止，不应继续输出额外 token。

“完全相同”的准确含义

理论上相同的是输出分布。随机数消耗顺序不同，同一个 seed 并不保证逐字一致。批量计算、浮点精度和不同 kernel 也可能带来数值差异。[2][5]

性能假设不参与正确性证明

精确性不要求草稿准确，也不要求各位置接受概率相互独立。只要使用正确的条件分布与校正规则，差草稿只会浪费时间，不会改变理论上的目标分布。

把常见解码方式放进来

Temperature、top-k、top-p：p、q 到底是哪一个分布？

本页的 p 是目标实际要采样的分布，即对 logits 施加 temperature、top-k / top-p、约束等处理并归一化后的结果；q 则必须是草稿真实使用的采样分布。接受比率与残差应使用这两个分布，不能混用原始 softmax 与截断后的概率。草稿与目标可以采用不同策略，但必须正确记录各自的实际概率。[1]

贪心解码：什么时候可以直接比较 token？

将目标 p 看成全部质量集中在 argmax token 的点质量，草稿提议只要等于目标 argmax 就接受，否则必被拒绝，纠正 token 就是目标 argmax。如果目标与草稿都使用贪心策略，算法退化成“比较连续匹配前缀，再补第一个不同的 token”。在一致的数值计算与 tie-breaking 下，它复现目标贪心序列。随机采样情形不能简单地照搬“token 必须相等”的高接受率直觉。

为什么只减少目标调用次数，还可能更慢？

每轮至少产出一个 token（假设尚未触发停止条件），所以目标调用次数不会比逐 token 解码更多。但草稿生成、批量验证、缓存调整与调度都要花时间。调用次数减少不等于墙钟时间下降；下一节把这些成本放在同一张图上。

06 / THE PRICE OF LOOKING AHEAD

猜得更多，
并不总是更快。

前面的草稿一旦失败，后面便白算了。
收益会饱和，成本却继续增加。

先建立一个可计算的简化模型。假设各位置的接受事件独立、接受概率都是 α；单个草稿成本是目标单步耗时 T 的 c 倍。若验证 γ 个候选的成本仍近似 T，一轮花费 (1 + γc)T。

记每轮输出的 token 数为 N。至少输出 1 个；要输出至少 2 个，第一个草稿必须通过；至少 3 个，前两个必须通过。用尾概率求和：

E[N] = 1 + α + α² + … + αγ
S ≈ 1 + α + α² + … + αγ1 + γcα = 1 时，E[N] = γ + 1；α < 1 时也可写成 (1 − αγ+1) / (1 − α)。

默认 α = 0.8, γ = 4, c = 0.1 时，平均每轮产出 3.3616 个 token，理论加速约 2.40×。把 γ 拉长：对于 α < 1，产出趋近于 1 / (1 − α)，但草稿成本仍在增长，所以可能存在中间最优点。

实际 α 会随前缀、领域和位置变化，接受事件也未必独立。更一般地，E[N] = ∑k=0…γ P(前 k 个全接受)；不能把任意实测平均接受率直接代入当作性能保证。[1]

A USEFUL TEST

当 γ = 1、b = 0 时，S = (1 + α)/(1 + c)。在这个模型中，α > c 才有加速；即使 α 很高，昂贵的草稿也可能吃掉收益。

07 / FROM ALGORITHM TO SYSTEM

公式之外，
还要让系统配合。

你现在可以用三个问题理解一个新方法：草稿从哪来、如何验证、代价是什么。

q

草稿不一定来自独立小模型

经典方案用一个更小的自回归模型。Prompt Lookup 复用上下文中的重复片段，适合有复制模式的任务；EAGLE 类方法利用目标模型特征来构造更准、更便宜的提案。不同草稿机制需要配套的正确验证规则。[6][7]

γ

草稿长度可以动态变化

容易的段落多猜几个，不确定时提前交给目标。动态 lookahead 尝试根据草稿置信度与运行状态分配工作；它改变“猜多远”，但不应绕过精确算法的接受与纠正规则。[8]

四个落地时必须对齐的细节

对齐分布和 token 空间

经典逐 token 校正假设 p 和 q 定义在同一组 token 上，不能把两个 tokenizer 的 token ID 直接相减。异构词表方案需要显式映射或其他专门算法。还要对齐每个位置的上下文、目标采样处理与约束；草稿保存的是实际提案概率。

对齐 logits 的位置与 KV cache

输入位置 j 的 logits 预测位置 j + 1。实现批量验证时必须确认首个分布对应当前前缀、最后一个分布对应全部草稿之后。拒绝后，目标与草稿两边都要使 KV cache 对应新确认的前缀；被拒绝及其后续候选的缓存不能继续沿用。新采出的纠正 / 额外 token 的 KV 尚需在后续前向中纳入，具体缓存排布由实现决定。

分清延迟、吞吐与资源占用

低到中等 QPS、访存受限的场景通常更有潜力。大 batch 已经提高计算利用率时，投机带来的额外 FLOPs、草稿权重、KV 内存与调度成本可能压缩收益。长上下文还会改变 KV 读取与验证成本，不能仅用参数量预测速度。[5]

用合适的指标验证

固定目标模型、输入集、采样参数、硬件与并发量，对比启用前后的每 token 延迟、端到端延迟（含 P50 / P95）、总吞吐与峰值显存；另外记录实际接受长度、草稿耗时和验证耗时。分布正确性用小词表枚举或采样收敛检验，贪心模式可用同配置的序列一致性检查。不要把相同 seed 的随机输出是否逐字相同当成无损标准。

树形草稿可以在一次验证里覆盖多条候选路径，但需要树形注意力、缓存管理与相应的采样算法。带有“投机”这个名字，也不自动意味着无损；如果放宽接受准则来追求更快，就要重新审视它是否保持目标分布。
